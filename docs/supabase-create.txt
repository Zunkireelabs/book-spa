  Step 5: Verification Checklist

  Run each of these in the SQL Editor to verify the schema is working correctly. Copy each block, run it, and check the expected
  result.

  5a. Tables created:
  SELECT table_name FROM information_schema.tables
  WHERE table_schema = 'public'
  ORDER BY table_name;
  Expected: attendance, bookings, branches, payments, rooms, services, therapists, users

  5b. Enums created:
  SELECT typname, enumlabel FROM pg_enum
  JOIN pg_type ON pg_enum.enumtypid = pg_type.oid
  ORDER BY typname, enumsortorder;
  Expected: All enum values for booking_status, discount_status_enum, payment_mode, payment_status_enum, user_role

  5c. Seed data present:
  SELECT 'branches' as tbl, count(*) FROM branches
  UNION ALL SELECT 'rooms', count(*) FROM rooms
  UNION ALL SELECT 'services', count(*) FROM services
  UNION ALL SELECT 'therapists', count(*) FROM therapists
  UNION ALL SELECT 'users', count(*) FROM users;
  Expected: branches=1, rooms=9, services=8, therapists=6, users=3

  5d. GIST exclusion — room overlap test:
  -- Insert a test booking
  INSERT INTO bookings (branch_id, room_id, service_id, customer_name, date, start_time,
    base_amount, discount_amount, final_amount)
  VALUES (
    'b0000000-0000-0000-0000-000000000001',
    'r0000000-0000-0000-0000-000000000001',
    's0000000-0000-0000-0000-000000000001',
    'Test Customer',
    CURRENT_DATE,
    '09:00',
    2500, 0, 2500
  );

  -- Try overlapping booking in SAME room (should FAIL)
  INSERT INTO bookings (branch_id, room_id, service_id, customer_name, date, start_time,
    base_amount, discount_amount, final_amount)
  VALUES (
    'b0000000-0000-0000-0000-000000000001',
    'r0000000-0000-0000-0000-000000000001',
    's0000000-0000-0000-0000-000000000001',
    'Overlap Customer',
    CURRENT_DATE,
    '09:30',
    2500, 0, 2500
  );
  -- Expected: ERROR conflicting key value violates exclusion constraint "excl_room_overlap"

  5e. Different room at same time (should SUCCEED):
  INSERT INTO bookings (branch_id, room_id, service_id, customer_name, date, start_time,
    base_amount, discount_amount, final_amount)
  VALUES (
    'b0000000-0000-0000-0000-000000000001',
    'r0000000-0000-0000-0000-000000000002',
    's0000000-0000-0000-0000-000000000001',
    'Different Room Customer',
    CURRENT_DATE,
    '09:30',
    2500, 0, 2500
  );
  -- Expected: Success

  5f. Booking number auto-generated:
  SELECT booking_number, customer_name, start_time, end_time
  FROM bookings ORDER BY created_at;
  Expected: Booking numbers like BK-20260212-0001, BK-20260212-0002

  5g. Datetime fields auto-computed:
  SELECT date, start_time, end_time, start_datetime, end_datetime
  FROM bookings LIMIT 1;
  Expected: end_time = start_time + 60 minutes (for Deep Tissue). start_datetime and end_datetime are full timestamps in UTC.

  5h. Discount CHECK constraint:
  -- Try approving discount without approver (should FAIL)
  UPDATE bookings
  SET discount_status = 'approved', discount_amount = 500
  WHERE booking_number = (SELECT booking_number FROM bookings LIMIT 1);
  -- Expected: ERROR new row violates check constraint "chk_discount_approval"
