# Session Log — 2026-07-22

## Focus: Calendar drag-lock rule — lock by start time, not by Confirmed status

### Investigation (two false starts before finding the real cause)
User asked why one MANJA booking (12:15pm–1:15pm) showed a lock icon while a later
Pending booking on the same day didn't.

- **First (wrong) answer:** attributed it to `status === 'Confirmed'` being locked,
  based on a stale sidebar tooltip string.
- **"Correction" (also wrong):** diffed `CalendarBookingCard.jsx` against local `main`
  and found no difference, concluded the lock must be the `is_locked` day-closed DB
  flag instead. This was wrong because **local `main` was stale** — it hadn't fetched
  `origin/main`.
- **Actual root cause**, found after `git fetch origin main` and diffing properly:
  commit `27cb046` ("feat(payments): hierarchical payment selector, previous-due
  bundling, and calendar lock fix", 2026-07-03, authored by Yukta Dhungana, promoted
  to production via PR #77 on 2026-07-19) **deliberately** added Confirmed/In-Progress/
  Completed to `NON_DRAGGABLE_STATUSES` and to the lock-icon condition. My working
  branch (`hotfix/thamel-therapist-optional`) had forked before this commit, which is
  why the earlier diff looked clean. The original answer was actually closer to right
  than the "correction" — the lock genuinely was status-driven, and intentional.

### Change: time-based lock replaces status-based lock
User's ask, after the above was clarified: a booking should lock only once it has
actually **started**, not simply because it's Confirmed. This intentionally reverts
part of commit `27cb046`'s behavior per explicit user request.

`src/pages/branch-manager-dashboard/components/calendar/CalendarBookingCard.jsx`:
- `NON_DRAGGABLE_STATUSES` back to `['Completed', 'Cancelled', 'No Show']` (terminal
  only — Confirmed/In-Progress removed).
- Added `getNepalNow()` / `isTimeLocked(booking)` — Confirmed/In-Progress now lock
  once `now (Asia/Kathmandu) >= booking.date + startTime`. Pending is exempt from the
  time lock (an overdue unassigned booking still needs to be reschedulable).
- Lock icon (`isLocked`) and `canDragBooking()` both now key off the same
  `isTimeLocked()` helper instead of a hardcoded status list, so the icon and the
  actual drag-ability stay in sync.
- Existing rules unchanged: paid and `isLocked` (day-closed DB flag, set only by
  `closeDay()` in `services/api.js`) still lock immediately regardless of time.
