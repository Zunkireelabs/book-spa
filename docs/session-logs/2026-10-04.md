### Round 2 — nav-cluster regroup, popover bleed-through fix, bigger drill-down calendar

After trying round 1 live, two more reference screenshots showed the real
Timely toolbar groups `« ‹ Today [date-field ▾] › »` as one adjacent cluster,
not split across the row — and the mini-calendar popover had a visual bug.

- Merged `‹`, `Today`, the date-field, and `›` into one bordered-group
  cluster (left-to-right), with the View By toggle immediately before it;
  restyled the date-field as a bordered box with a trailing `ChevronDown`,
  matching the reference's `Sun, Oct 4, 26 ⌄` look. Added `«`/`»`
  double-chevron buttons flanking the cluster that open a jump-options
  dropdown (±1–8 weeks, ±6 months, ±1 year via a new `applyJump()` +
  `addMonths()` helper) rather than an instant ±7-day jump, matching the
  reference's own dropdown behavior (confirmed via two more screenshots of
  the reference's `«`/`»` menus).
- **Popover bleed-through bug** — confirmed root cause via code read:
  `CalendarGrid.jsx`'s fixed header row wrapper (both the day-view render
  path and the duplicate multi-day/4-day path) applied `z-header` to a
  statically-positioned `div`; a `z-index` on a non-positioned element is
  inert per the CSS spec, so staff column-header text visually bled through
  the open date popover instead of sitting under it. Fixed by adding
  `relative` to both header-row wrapper `className`s in `CalendarGrid.jsx`,
  which lets `z-header` (100) actually establish a stacking context below
  the popover's `z-dropdown` (300). Verified both render paths are reachable
  (day view and 4-day view), not dead code.
- Toolbar restructured to a `sm:grid sm:grid-cols-[1fr_auto_1fr]` layout
  (View By left, nav cluster `justify-self-center`, right section
  `justify-self-end`) so the nav cluster is genuinely centered across the
  toolbar, not just centered in the leftover gap next to View By.
- `formatDateTitle()` had a `"Today"` shortcut for the current date that
  collided visually with the adjacent "Today" button (both read "Today",
  making the field look off-balance/uncentered) — removed the shortcut so
  the date field always shows the actual formatted date.
- `MiniMonthCalendar.jsx` popover was cramped (28px day cells, 10–12px text)
  versus the reference's roomier calendar — resized to 44px cells/text-base,
  340px popover width, and centered the popover under the date field
  (`left-1/2 -translate-x-1/2` instead of `left-0`, now safe since the
  bleed-through fix above means a centered popover no longer gets rendered
  over by header text). Confirmed this component has only the one call site,
  so resizing it directly was safe.
- Added month/year drill-down to `MiniMonthCalendar.jsx` (clicking the
  "October 2026" header shows a 12-month grid for the year; clicking that
  header shows a 12-year grid), matching reference behavior the user pointed
  out was still missing. New `pickerMode` ('days'/'months'/'years') state;
  prev/next arrows step by month/year/year-range depending on mode.

### Round 3 — white overscroll-flash fix

User reported a plain-white flash during trackpad rubber-band
overscroll/drag-scroll, reproduced on `/dashboard` generally (not just the
calendar route). Two causes found and fixed:

- **Genuine regression from round 1**: removing the old sidebar's row-flex
  wrapper (`flex flex-1 min-h-0`) left the calendar-grid div as a direct
  child of a column-flex container without `min-h-0`. Flex items default to
  `min-height: auto` (their content's intrinsic height), so on short
  viewports / when the denser round-2 toolbar wraps to 2 lines, the grid
  could refuse to shrink and push real content past the viewport, causing
  genuine page scroll. Fixed: `index.jsx`'s grid wrapper
  `flex-1 overflow-x-auto md:overflow-hidden` → `flex-1 min-h-0
  overflow-x-auto md:overflow-hidden`.
- **Pre-existing but exposed by the above**: `html` had no explicit
  `background-color` anywhere (`src/styles/tailwind.css` only set it on
  `body`), and separately, macOS trackpad rubber-band in Chromium-based
  browsers (Brave, confirmed via the user's screenshot) paints its own
  native glow/bounce during overscroll that ignores page background styling
  entirely — so even after adding an explicit `html { @apply bg-background;
  }` rule, the white flash persisted (confirmed via a follow-up screenshot
  on `/dashboard`, not calendar-specific). Fixed by adding
  `overscroll-behavior-y: none;` to both `html` and `body` in
  `tailwind.css`, disabling the bounce/glow effect outright rather than
  trying to recolor it.
