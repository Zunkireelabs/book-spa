## Key Decisions / Lessons

1. **CI build is verification only — prod build runs on the prod server.** `VITE_*` env vars consumed by the production bundle must be set in `docker-compose.yml` build args, **not** GitHub Actions secrets. GitHub secrets only cover the CI verification build. This burned ~2 deploys before being identified; worth a CLAUDE.md update.
2. **PostHog `phc_` project keys are publishable and safe to commit** (same security posture as `anon` Supabase keys — RLS / project-scoping enforced server-side).
3. **Deliberate workflow break: PostHog promoted feature → main directly**, skipping `stage`. This was at explicit user request to avoid bringing the membership system to `main` ahead of testing. Not a pattern to repeat without that same explicit instruction.
4. **Auto-mode classifier blocked a destructive cherry-pick fallback** (bulk `sed` to strip membership refs). Manual reapply onto `main` was the correct path. Worth keeping the trigger sensitive here.
