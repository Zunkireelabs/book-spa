# Session Log — 2026-11-02

## ZNLY-186: Per-branch service scope (standalone, targets `stage`)

Re-implements the already-reviewed (9.5/10) per-branch-service-scope design from
ZNLY-186's sibling ticket, but as a standalone branch off `origin/stage` so it can ship
without waiting on the large, unreviewed `fix/admin-viewer-membership-voucher-package-access`
branch. Branch: `feature/ZNLY-186-branch-service-scope-prod`.

### Files changed

- `supabase/migration-313-branch-service-links.sql` (new) — `branch_service_links` table
  (inclusion convention: zero rows = Overall/visible everywhere, N rows = restricted to
  those N branches), SELECT-only RLS policy, `set_service_branches(p_service_id, p_branch_ids)`
  SECURITY DEFINER RPC (manager/admin only, org-scoped, granted to `authenticated` not `anon`).
- `src/services/api.js`:
  - New `filterServicesByBranchScope(services, branchId)` module-scope helper (~line 191, just
    above `fetchServices`).
  - New `fetchServiceBranches(serviceId)` and `setServiceBranches(serviceId, branchIds)` exports,
    added next to `fetchServiceTherapists`/`setServiceTherapists` (~line 6251+).
  - `fetchServices(branchId)` (line 191) and `fetchBookableServicesByOrgSlug(orgSlug, branchId)`
    (line 10595) refactored from early-return to an accumulator (`let filtered = data`) so the
    `excluded_service_categories` filter and the new branch-scope filter both apply instead of
    whichever ran first.
- `src/pages/branch-manager-dashboard/components/MasterData/ServiceManagementPanel.jsx`:
  - New state: `allBranches`, `eligibleBranchIds`, `restrictBranches`, `branchSearchQuery`
    (~line 33-36), fetched via `fetchBranchesByOrgId(orgId)` on mount (new `loadBranches`
    callback, mirrors `loadTherapists`).
  - New "Restrict to specific branches?" toggle + searchable checklist block in the Add/Edit
    modal, placed right after the existing "Restrict to specific staff?" block — same markup
    shape (toggle switch, search `Input`, `max-h-[220px]` scrollable list, `bg-primary/5`
    highlight), showing branch names.
  - `handleOpenCreate`/`handleOpenEdit` reset/populate the new branch state the same way the
    existing staff-eligibility state is handled; `handleOpenEdit` additionally calls
    `fetchServiceBranches(editingService.id)` and sets `restrictBranches = (result.length > 0)`.
  - `handleSave` calls `setServiceBranches(serviceId, restrictBranches ? eligibleBranchIds : [])`
    right after the existing `setServiceTherapists` call, with the same non-fatal error handling
    (service/staff already saved; surface the branch-scope error and keep the modal open rather
    than silently dropping it).
