## Session 2 — `fix/attendance-time-column-drift`

### Focus: prod incident — client unable to create bookings

Client screenshot showed `operator does not exist: timestamp with time zone
>= time without time zone` on Create Booking submit.

### Root cause

`therapist_attendance.check_in_time` / `check_out_time` on **prod** were typed
`time without time zone`, not `timestamptz` — undocumented ad hoc drift, same
failure class as the 038–041 and migration-150a incidents (schema changed
outside any tracked migration file, so `scripts/migrate-status.sh` reported
prod as fully up to date even though it wasn't). Confirmed via `\d
therapist_attendance` against both pooler hosts:

- prod (`aws-1-ap-northeast-2.pooler.supabase.com` /
  `postgres.pmbvogiphelmpjdalmtv`): both columns `time without time zone`
- staging (`aws-1-ap-south-1.pooler.supabase.com` /
  `postgres.snzcckzfmpboeqkktmwy`): both columns `timestamptz` (matches
  `migration-002-missing-tables.sql`)

`check_therapist_booking_guards` (migration-252/257/258) runs `IF
v_attendance.check_out_time IS NOT NULL AND p_start_datetime >=
v_attendance.check_out_time` — `p_start_datetime` is `timestamptz`, so the
comparison threw on prod for any therapist with a recorded checkout,
blocking booking creation.

### Files created

- `supabase/migration-261-fix-attendance-time-columns.sql` — idempotent
  `DO` block (same pattern as migration-150a): guarded on
  `information_schema.columns.data_type`, `ALTER COLUMN ... TYPE timestamptz
  USING (date + col) AT TIME ZONE 'Asia/Kathmandu'` for both columns,
  no-op where already `timestamptz`. Self-records version 261.

### Verification done this session

- Queried prod: `SELECT count(*), count(check_in_time), count(check_out_time)
  FROM therapist_attendance` → 1836 rows, 0 with either column populated —
  confirmed the `USING` cast had no real data to reinterpret before applying.
- Applied migration-261 directly to prod via `scripts/migrate-apply.sh prod`
  (`PGHOST=aws-1-ap-northeast-2.pooler.supabase.com
  PGUSER=postgres.pmbvogiphelmpjdalmtv`) — `DO` / `INSERT 0 1` succeeded.
- Re-ran `\d therapist_attendance` against prod post-apply — both columns
  now `timestamp with time zone`, matching staging/repo.
