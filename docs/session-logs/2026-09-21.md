### demospa PIN login — actual root cause found, not the rate limit
The `is_super_admin` fix from earlier wasn't the whole story. Systematic root-cause pass
against prod `auth.users`, comparing all 9 broken accounts to a known-working account
(`admin@nuadthainepal.com`) column-by-column: found `email_change` and
`email_change_token_new` were `NULL` on all 9 (the raw-SQL `INSERT` never set them), vs
`''` (empty string) on every real GoTrue-created account. GoTrue's Go struct scans these
as non-nullable strings — `NULL` breaks any auth operation touching the row, surfaced by
`pin-login` as the generic "Failed to generate session token".
- Fixed in place: `UPDATE auth.users SET email_change = '', email_change_token_new = ''`
  for all 9 demospa accounts on prod (ran with explicit user approval — direct prod
  mutation gets blocked by the auto-mode classifier otherwise).
- Fixed at the source: `supabase/seed-prod-demospa-credentials.sql`'s `INSERT INTO
  auth.users` now sets both columns to `''` explicitly, and the header comment documents
  this as incident #2 (alongside the existing `is_super_admin` one) so any future raw-SQL
  `auth.users` insert copies the full set of GoTrue-required empty-string defaults.
- Verified via re-query: all 9 accounts now show `''`, not `NULL`, in both columns.

## Continued (later same day) — PR #286 pre-merge fix: package leaf wiped split payments

Code review of PR #286 (not yet merged) surfaced a real gap: `redeemPackage(pkg)` does a
full `setTenders([...])` replace, correct for the normal single-tender case but silently
destructive if triggered from row 2+ of a multi-method split payment (added via "+ Add
method") — staff picking "Package — ..." there would wipe every already-entered row with
no warning. Root cause: package redemption is inherently a whole-payment-replace action
(server computes the redemption value from the booking's own remaining balance), which is
incompatible with split payments by design — not something to patch around after the wipe.

- `src/components/ui/PaymentModal.jsx` — gated `packageLeaves` on `tenders.length <= 1` in
  addition to the existing `remaining > 0` check, so the package dropdown option
  disappears from every row the moment a second tender row is added, and reappears if the
  split is collapsed back to one row. Single source point — already spread into all three
  `extraLeaf` call sites, so no other file changes needed.
- `npm run build` passes. Manual staging verification (single-row option present, 2-row
  option absent from both rows, reappears after removing back to 1 row, redemption still
  works end-to-end) still pending — not done this session.
- Pushed as `8021d4f` directly onto `feature/package-type-management-ui`, updating the
  existing PR #286 (no new PR).
