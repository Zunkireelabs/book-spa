# Session Log — 2026-10-13

**Branch:** `stage`

## Focus: group booking name/phone validation + fallback bug

Bug report: staff-side group booking quick-create (manager/staff calendar)
required name+phone for every person, when only person 1 ("booking contact")
should be required — persons 2+ should be optional and inherit person 1's
name+phone if left blank. The per-row UI placeholder already implied this
("optional" for persons 2+), masking that validation enforced the opposite.

Root cause: `groupValid` used `people.every(...)` over name+phone, requiring
all rows instead of just `people[0]`. `buildGroupPeople()` already had a
lead-fallback for name/email/gender but explicitly skipped phone (stale
comment: "no phone fallback here" — leftover from when validation forced
every row to have its own phone).

### Files modified

- `src/pages/branch-manager-dashboard/components/calendar/index.jsx`
  - `groupValid` — now only requires `people[0]`'s name + phone (plus
    `groupServiceValid`), not every person's.
  - `buildGroupPeople()` — added `leadPhoneDigits`/`leadCountryCode` fallback
    for persons 2+ when their own phone is blank, mirroring the existing
    name/email/gender fallback pattern. Updated stale comment.
  - Person-row phone `<input>` placeholder (idx > 0) now reads "Phone
    (optional — uses booking contact if blank)" instead of unconditionally
    "Phone (required)", matching the name placeholder's existing pattern.

No changes to `services/api.js` — `createBooking()`'s existing `!customerPhone`
guard still holds since every person now resolves to a non-null phone (own or
lead's) before the call.
