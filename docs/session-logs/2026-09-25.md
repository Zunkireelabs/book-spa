# Session Log — 2026-09-25

## Focus: "New" customer tag on calendar booking cards

User shared a screenshot of the branch-manager calendar (`OperationalCalendar.jsx`) noting bookings for first-time customers had no "New" indicator, unlike the existing "New" badge already shown inside the booking-details/action modals.

- Found the existing pattern: `getCustomerFirstBookingFlag()` (`services/api.js`) answers "does this customer have any earlier non-Cancelled booking?" (walk-in/guest with no `customer_id` always counts as first) and is consumed one booking at a time by `BookingActionModal.jsx` and `booking-details-assignment-modal`'s `BookingDetailsPanel.jsx` to render a `bg-success/10 text-success` "New" pill.
- That per-booking query isn't viable for a calendar view rendering many events at once, so extended `getCalendarBookings()` (`services/api.js`) instead:
  - Added `customer_id` to the bookings select.
  - After fetching the range's bookings, batch-fetched the earliest non-Cancelled booking id per distinct `customer_id` present (one extra query for the whole batch, not one per event) and tagged each booking with `isNewCustomer` using the same "no customer_id → always new" rule as the modal helper.
- `OperationalCalendar.jsx`: passed `isNewCustomer` through into each FullCalendar event's `extendedProps`, and rendered the same "New" pill next to the customer name in `renderEventContent`.
- Verified via `npm run build` (passed).
- Branched `feat/calendar-new-customer-tag` fresh off `origin/stage` to isolate this change — the branch the work started on (`feat/transfer-edit-and-block-preview`) had unrelated uncommitted changes (StaffSidebar, VoucherDetailModal, BookingConfirmation, an in-flight `createBooking` client-request-id change in `api.js`) that shouldn't ride along in this PR; those were stashed and left untouched.

### Outcome
PR opened: `feat/calendar-new-customer-tag` → `stage`.
