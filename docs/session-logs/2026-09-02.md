## Focus: Session-Based Service Packages — final whole-branch review + fix wave

### Final review findings (caught only by reviewing all 5 tasks merged together)
Per-task reviews each passed on `npm run build`, which can't catch a PostgREST relationship error or
an RLS-bypassed view — those only surface once the merged code runs against a real DB. The final
reviewer verified two of the three Critical findings empirically against the live staging DB rather
than just reading code:

1. **Critical, fixed:** `packages.issued_by`/`package_redemptions.performed_by` referenced
   `auth.users` (a plan defect — Task 1's brief specified `auth.users`, not `public.users` like
   migration-072's vouchers). `auth` isn't PostgREST-exposed, so every manager-UI list/detail query
   embedding `issuer:users!issued_by(...)` would have thrown PGRST200 — the entire Task 4 manager UI
   was dead on arrival against a real database. Fixed: both columns now `REFERENCES public.users(id)`.
2. **Critical, fixed:** `package_balances` view had no `security_invoker = true`, bypassing RLS.
   Confirmed empirically that the sibling `voucher_balances` view already leaks this exact way on
   **production today** — 155 voucher rows readable by the `anon` role across every org (see below).
   Fixed for `package_balances`; `voucher_balances` is a pre-existing separate issue, not touched.
3. **Critical, fixed:** `SessionPackage` redemptions (which correctly post a real payment amount so
   bookings can settle) were missing from 4 platform-revenue exclusion lists (migration-116/117's
   `platform_org_sales_base`/breakdowns, `PlatformOrgDetail.jsx`), so every redemption would have been
   double-counted as new platform billing revenue. Fixed via new `migration-142`.
4. **Important, fixed:** `getDailyOperationalReport` disagreed with `getDailySummary` specifically for
   SessionPackage days (closeDay persists getDailySummary's number) — a new reconciliation bug this
   branch introduced. All three daily-reporting functions (`getDailySummary`,
   `getDailyOperationalReport`, `getTodayInsights`) now apply one consistent policy.
5. **Important, fixed:** seed script wrote `guest_info` as a bare 10-digit phone; the manager-UI modal
   writes E.164; the redemption lookup does exact-string match — format mismatch would have made
   imported packages without a resolved `customer_id` silently unreachable at checkout. Seed script
   now writes E.164, matching everywhere else.

Fix wave (one commit, `617eab9`) + one scoped re-review: all 5 ADDRESSED, no new breakage.
`npm run build` reconfirmed clean.
