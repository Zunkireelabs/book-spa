### Double-counting fix (payments grain, not booking grain)
A booking's `final_amount` can include amounts paid via membership/voucher wallet redemption,
which would double-count against the Paid Memberships/Vouchers lists if shown as-is. Fix: compute
each booking's **non-wallet payment sum** client-side from the `payments[]` array
`platform_get_org_bookings` (migration-117) already returns per booking (unused until now) —
excluding `payment_mode IN ('Membership','ReferralWallet','VoucherWallet','ReferralVoucher')`,
same list as migration-116. Bookings paid entirely via wallet net to 0 and are dropped (already
represented in the other two lists).

## Focus (continued): fix PR #138 review findings on Org Detail commission wizard

User re-checked PR #138 and pasted 4 unresolved review findings (all in
`src/pages/platform/PlatformOrgDetail.jsx`, unchanged since last review). Fixed all 4 directly, no
plan needed (bounded, single-file):

1. **Default range regression for a brand-new org** — `uncollectedSince` memo fell through to
   `getTodayISO()` when an org has zero collections AND zero rates, defaulting the wizard to
   today→today and silently hiding all historical uncollected sales. Restored an all-time sentinel
   fallback (`const ALL_TIME_FROM = '2000-01-01'`, added near `dayAfter()`) instead — matches the
   documented "show Total sales till date" default.
2. **Stale caption copy** — drill-in caption still said `"Sales (range)"`; the wizard field was
   renamed to `"Sales (period)"`. Updated the caption to match.
3. **Raw z-index** — sticky `<thead>` used `z-10` instead of the semantic token. Swapped to
   `z-sticky-filter` per CLAUDE.md's semantic-z-index rule.
4. **No numeric validation on VAT%/Cut% inputs** — Collect button's `disabled` check only guarded
   `!wizRateNum`; garbage VAT% input let `wizVatNum` go `NaN`, which the server's
   `COALESCE(p_vat_rate, 13.00)` would silently substitute 13% for on submit (JSON.stringify(NaN)
   sends null) — a mismatch between what's confirmed on screen and what's recorded. Extended the
   guard: `disabled={!wizRateNum || Number.isNaN(wizVatNum) || wizRateNum < 0 || wizVatNum < 0}`.
