### Migration 231

`supabase/migration-231-codify-role-statement-timeouts.sql` writes the four
role timeouts as a tracked, self-recording migration. No-op on prod (writes
back what it holds); raises staging 8s → 30s so staging reproduces production's
timeout behaviour — a load test passing under a stricter ceiling proves nothing
about prod.

Recorded in the header: 30s is a saturation-era ceiling kept because it is
proven, not because it is right, and must not be lowered before the RLS plan
complexity work (671-node plans, 325+ nested InitPlans) that migration 228's
header already argues for. `anon` stays at 3s as the only unauthenticated role.
`service_role` deliberately gets no role-level timeout. No
`pg_terminate_backend` recycle — that is the migration-227 mistake.
