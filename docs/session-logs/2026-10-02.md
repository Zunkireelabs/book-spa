### Edge case 1 — UTC vs Nepal date bug in the backdate date-picker's `max`

`toDateInputValue(date) { return date.toISOString().slice(0, 10) }` uses
`.toISOString()`, which is UTC. Nepal is UTC+5:45, so during roughly
18:15–23:59 UTC, Nepal's calendar date has already rolled to tomorrow while
this helper still returns yesterday's UTC date — the date picker's `max`
can be one day behind real Nepal "today" in that window.

Found the identical buggy helper copy-pasted in 5 files, none importing a
shared util. A correct pattern already existed in
`src/pages/customer-booking-flow/utils/availability.js` (`en-CA` locale +
`timeZone: 'Asia/Kathmandu'`).

- Files created:
  - `src/utils/date.js` — shared `toDateInputValue(date)`, using
    `date.toLocaleDateString('en-CA', { timeZone: 'Asia/Kathmandu' })`.
    Same name/signature as the old local copies, so every call site
    (including non-"today" callers like `NewVoucherModal.jsx`'s
    `expiryDate` calc) kept working unchanged after the import swap.
- Files modified (deleted local `toDateInputValue`, added shared import):
  - `src/pages/branch-manager-dashboard/components/Memberships/EnrollMemberModal.jsx`
  - `src/pages/branch-manager-dashboard/components/Packages/NewPackageModal.jsx`
  - `src/pages/branch-manager-dashboard/components/Vouchers/NewVoucherModal.jsx`
  - `src/pages/branch-manager-dashboard/components/Vouchers/VoucherDetailModal.jsx`
  - `src/pages/branch-manager-dashboard/components/Campaigns/CampaignsPanel.jsx`
- `src/pages/customer-booking-flow/utils/availability.js` left untouched —
  already correct, out of scope.

### Edge case 2 — `created_at` stamped at UTC midnight, not Nepal midnight

`migration-234-membership-enrollment-backdate.sql` set
`created_at = p_activation_date::timestamptz` on backdate, which Postgres
resolves as midnight UTC rather than midnight in Asia/Kathmandu (the
timezone the same RPC uses everywhere else, e.g. `v_today`). Cosmetic — the
UI only shows the date part — but internally inconsistent and could skew
same-day sort order.

- Files modified:
  - `supabase/migration-234-membership-enrollment-backdate.sql` — both the
    `memberships.created_at` and `membership_transactions.created_at`
    overrides now read
    `p_activation_date::timestamp AT TIME ZONE 'Asia/Kathmandu'` instead of
    `p_activation_date::timestamptz`; the "Why membership_transactions.created_at
    is also overridden" comment block got a new paragraph explaining the
    Nepal-midnight fix.

**Branch:** `feat/sales-by-category-report`

## Focus: fix bookings charging full price instead of active offer/campaign price

Live financial bug: every booking made against an offer/campaign-priced
service since offer pricing shipped (PR #296, migrations 195-211) was
overcharging relative to the price Service Management and the customer
picker displayed. Root cause: `createBooking()` and `fetchServices()` read
the plain `services` table (raw `price_npr`) instead of the offer-aware
`services_with_offer_pricing` view (`effective_price_npr`) that Service
Management and the public customer picker already used. No DB trigger
recomputes `base_amount` from offers — pure missing-join bug in app code,
no migration needed.

- Files modified (`src/services/api.js`):
  - `fetchServices()` (used by StaffBookingForm + Calendar dropdowns) —
    switched `.from('services')` to `.from('services_with_offer_pricing')`,
    added `effective_price_npr, is_on_offer, original_price_npr` to select.
  - `createBooking()` — same table switch for its internal service lookup;
    `base_amount` and `service_price_snapshot` now stamp from
    `service.effective_price_npr` instead of `service.price_npr`.
    `effective_price_npr` is never null (the view's
    `compute_service_offer_pricing()` falls through to the plain price when
    no offer applies), so this is a safe drop-in with no behavior change
    for non-offer services.
- Files modified (price labels, so staff see the price that will actually
  be charged before booking):
  - `src/pages/branch-manager-dashboard/components/calendar/index.jsx`
    (3 service-picker dropdowns)
  - `src/pages/branch-staff-dashboard/components/StaffBookingForm.jsx`
    (service list row + order-summary total)
  - All switched from `s.price_npr` to `s.effective_price_npr ?? s.price_npr`.
