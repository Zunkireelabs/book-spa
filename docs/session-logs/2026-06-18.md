## Key Decisions / Lessons

1. **Cherry-pick hotfix is now the established pattern for "production needs feature X but stage is carrying unrelated WIP Y."** Used twice now (PostHog on 2026-06-15, discount-to-100% today). The standard `stage → main` flow stays the default — divergence requires explicit user authorization, like both of these have.
2. **Always state DB hand-off scope explicitly before opening a promotion PR.** User caught the membership migrations sneaking into the discount hand-off only by inspecting the SQL — would have been a silent feature ship otherwise. The CLAUDE.md `> [!IMPORTANT]` block on DB promotion already says this; reinforcing it here.
3. **Two distinct semantic constants beat one overloaded constant.** Replacing `MAX_DISCOUNT_PERCENT` with `DISCOUNT_LIMITS` + `STAFF_REQUEST_CEILING` made the role-aware ceiling check trivial and the intent self-documenting; would have been muddled if reused with conditional fallback math.
