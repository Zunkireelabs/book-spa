## Focus (continued): fix scroll jump on booking view open/close

User-reported: opening the booking view from a scrolled-down profile page
visibly animated the page scrolling back to top (and repeated on every
step change) — disorienting on a full-height page. Root cause: the
step-change scroll-reset effect fired on mount too, not just on step
changes, and used `behavior: 'smooth'`, so the mount-time reset to top
visibly travelled the whole scroll distance instead of just starting there.
(A second reported symptom — stale "No service selected yet" singular text
on the summary card — was a stale-HMR-bundle artifact, not a code defect;
no fix needed, confirmed by the file on disk already reading the correct
plural/updated string.)

  `[stepIndex, showConfirmation]` scroll-reset effect: `behavior: 'smooth'`
  → `'auto'`, so the reset is instant (reads as a normal screen change)

## Focus (continued): scroll jump fix — proper root-cause pass (prior fix was incomplete)

Prior `'smooth'` → `'auto'` edit (above) was insufficient: `behavior: 'auto'`
means "obey CSS `scroll-behavior`", and `customer-booking-flow-v2/index.jsx`
adds `html.smooth-scroll` (CSS `scroll-behavior: smooth`) on every render —
including when it early-returns `<ProviderProfileFlow />`, since hooks run
before the return. So resets were still animated. Second cause: the reset
ran in a `useEffect` (post-paint), so the new (much shorter) page painted
first at the old `scrollY`, got clamped to `scrollHeight - innerHeight`
(the visible downward lurch), and only then glided to 0.

### Files modified

- `src/pages/provider-profile-flow/components/BookingView/index.jsx` — step
  change reset: `useEffect` → `useLayoutEffect` (runs before paint, no
  clamp) + `window.scrollTo({ top: 0, behavior: 'auto' })` → `scrollToTopInstant()`
  (temporarily overrides inline `scroll-behavior`, immune to the
  `smooth-scroll` class; avoids `behavior: 'instant'`, which throws on
  Safari < 17.4). Added `useLayoutEffect` import and
  `scrollToTopInstant` import from `utils/scroll`.
- `src/pages/provider-profile-flow/index.jsx` — same substitution
  (`scrollToTopInstant()`) in `closeBooking` and the `popstate` handler.

### Explicitly out of scope

- `html.smooth-scroll` left untouched — V2's own wizard branch wants it;
  `scrollToTopInstant` is immune to it by design, so scoping the class is a
  separate, riskier change not needed here.
- `useScrollSpy`'s pill-bar `behavior: 'smooth'` / `scrollIntoView` left
  untouched — intentional user-initiated animation, not part of this bug.
- Scroll-restore-to-prior-position on close not changed — still resets to
  top, which was already the existing (different) behavior.
